predictive-autoscaler {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

New autoscalers run in Recommend mode: they publish recommendations and change nothing until you set
spec.mode: Active on each one. Forecasts need a successful training per autoscaler (training.targets): by default
it trains on up to 7 days of request history and needs at least 235 usable 10-minute points (about 39 hours); until
then the reactive rule applies.

{{- if .Release.IsUpgrade }}

Upgrade: Helm never upgrades the CRD in crds/. If this version ships a newer CRD, apply it first (to the cluster
this release is in):
  kubectl --kubeconfig <file> --context <context> apply --server-side --force-conflicts -f charts/predictive-autoscaler/crds/
The operator logs the CRD revision it found and the one it requires, and waits until the installed revision is at
least the required one.
{{- end }}
{{- if and (eq .Values.forecaster.tls.source "selfSigned") .Values.forecaster.auth.enabled }}

TLS: the forecasting service uses a self-signed certificate (Secret {{ include "pa.fullname" . }}-forecaster-tls). It is
NOT renewed automatically, and changing selfSigned.validityDays does not renew an existing one (upgrades keep it).
Check the real expiry (notAfter) of the certificate in that Secret's tls.crt; before it, delete the Secret and run
helm upgrade. For production prefer forecaster.tls.source=certManager (automatic renewal).
{{- end }}

volume and every trained model. Turning retain off on a running release also makes a later delete remove it.
